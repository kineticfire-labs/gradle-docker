  Your task is to help design a new feature for the 'dockerTest' DSL.  The DSL is used for testing Linux (Docker) images.  The DSL defines configuration blocks:
  - waitForHealthy -- which waits for a container to be in the 'healthy' state, if it supports a health check
  - waitForRunning -- which waits for a container to be in the 'running' state, if the container does not support a health check

  Both blocks accept a list of 1 or more containers to wait for using 'waitForService' and a timeout using 'timeoutSeconds'.  These can be used by themselves or
  together.

  The new feature to design is related:  we want to be able to wait on certain output (string) to appear in the logs to determine that a container is ready.  Like the
  two blocks described earlier, this should work on 1 or more containers, have a timeout in seconds, and be useable by itself or in conjuction with waitForHealthy
  and/or waitForRunning.

  We need to look for certain log output per container to determine that the container is ready, such log output might be "Service started" or "ready".  It may be
  best to accept a regex string.  In order to help the user simplify potentially complex regexes, should we accept more than 1 regex string per container?  Since we
  now need a regex string (or more) per container to determine if it's ready, we can't accept just a list as with the other waitForHealthy and waitForRunningBlocks;
  it might be better to use a map with:  <service name> -> <regex>

  I envision the block would be something like:

  waitForLog {
     waitForService.set( map as above for 1 or more containers to regex )
     timeoutSeconds.set(60)
  }

  We can assume that, since we are working with Docker containers, that the log output of the container is properly directed to stdout (as is best practice for Docker
  containers) so we can logs as such.

  Consider ONLY the DSL aspect first so we can focus on how a user would use this DSL from the plugin so that we can ensure user experience is the best.

  Read the usage document for 'dockerTest' at @docs/usage/usage-docker-test.md to understand the 'waitForHealthy' and 'waitForRunning' DSLs, since the operation of
  this 'waitForLog' should be similar.

  Analyze this feature description, provide a design that includes answers the to asked question, and give feedback and recommendations.  Do NOT edit code.
